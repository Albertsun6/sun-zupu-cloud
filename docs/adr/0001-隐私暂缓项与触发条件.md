# ADR-0001 隐私暂缓项与触发条件

- 状态:已接受(2026-07-07,健康度评审 E4 固化)
- 决策人:用户(2026-06-30 明确暂缓)

## 背景

两项已知隐私风险,用户在 2026-06-30 工程化审计时**明确决定暂缓**(当前所有账号均为家族内可信成员):

1. **history 表 PII 对 viewer 可读**:`policies.sql` 把 history 列入"任意登录可读",而 `logHist` 将含 `contact`/`address` 的 before/after 明文入库 → 任何 viewer 账号可经 API 读到联系方式/住址变更史。
2. **照片为公开桶**:`photos` 桶 public=true(对象名 uuid 不可枚举,但知道 URL 即可访问)。

## 决策

维持现状**直到触发条件发生**;这是有意的取舍(全员可信 + 简单性),不是遗漏。

## 触发条件(任一发生,必须先做完再执行)

> **把 viewer/任何账号发给家族外或半信任成员之前**,必须先落实:
> 1. history 列级脱敏:`logHist` 入库前对 `contact`/`address` 打码(前端 diff 已打码,库内未);
> 2. 照片改私有桶 + 签名 URL(参照 recordings 桶的做法,minutes.sql 有现成模板)。

## 备注

v0.41 的 recordings 新桶已按"默认私有+签名URL"建(旧教训被吸收);本 ADR 只管存量两项。
